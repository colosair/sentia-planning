# SENTIA 문서 안내

이 디렉터리는 SENTIA의 제품 기획, 역할, 시스템 구조, 프로젝트 범위와 조사 기록을 관리한다.

처음 보는 경우 **01 → 02 → 03 → 04** 순서로 읽는 것을 권장한다.

> 저장소 전체 소개로 돌아가기: [SENTIA 메인 README](../README.md)

## 현재 정본

다음 네 문서가 현재 팀이 공유하는 기획·설계 기준이다.

| 순서 | 문서 | 답하는 질문 | 주요 내용 |
|---|---|---|---|
| 01 | [프로젝트 개요](./01-project-overview.md) | 왜 만들고 무엇을 해결하는가? | 배경, 핵심 문제, 대상 사용자, 제품 방향 |
| 02 | [팀과 역할](./02-team-and-roles.md) | 누가 무엇을 책임지는가? | AI·백엔드·프런트엔드 역할과 책임 경계 |
| 03 | [시스템 개념](./03-system-concept.md) | 시스템이 어떻게 동작하는가? | 현실 관측부터 판단·조치·보고까지의 정보 흐름 |
| 04 | [범위와 계획](./04-scope-and-plan.md) | 이번 프로젝트에서 어디까지 만드는가? | 범위, 일정, 진행 관문, 합의 항목, 조건부 확장 |

### 문서 간 관계

| 문서 | 중심 역할 |
|---|---|
| [01 · 프로젝트 개요](./01-project-overview.md) | 제품의 문제와 방향을 정의한다 |
| [02 · 팀과 역할](./02-team-and-roles.md) | 제품 구조를 팀 책임으로 나눈다 |
| [03 · 시스템 개념](./03-system-concept.md) | 정보와 상태가 시스템 안에서 어떻게 흐르는지 정의한다 |
| [04 · 범위와 계획](./04-scope-and-plan.md) | 실제 일정 안에서 구현할 깊이와 범위를 관리한다 |

제품 정의를 확인할 때는 01, 역할 경계를 확인할 때는 02, 시스템 흐름을 확인할 때는 03, 일정과 범위를 확인할 때는 04를 기준으로 한다.

## 조사·논의 기록

[00-discovery/](./00-discovery/)에는 현재 정본에 도달하기까지의 조사와 논의 과정을 보관한다.

이 기록은 현재 기획을 대신하는 정본이 아니다. 과거 가설, 당시의 기술 후보, 이후 변경된 판단이 함께 포함될 수 있다.

### 세션별 기록

| 기록 | 주요 주제 |
|---|---|
| [01 · 프로젝트 방향과 역할](./00-discovery/sessions/01-project-direction-and-roles.md) | 초기 제품 방향, 실무 조사, 역할 구조, 비전 파이프라인 |
| [02 · 공간 코어와 Unreal 확장](./00-discovery/sessions/02-spatial-core-unreal-expansion.md) | 2D·2.5D 공간 구조, 좌표 체계, Unreal 확장 방향 |
| [03 · 3DGS·데이터·시연 환경](./00-discovery/sessions/03-3dgs-data-demo-environment.md) | 3DGS, 데이터 확보, 공개 데이터, 시연 환경 |
| [04 · 안전 업무 흐름과 현실 연결](./00-discovery/sessions/04-safety-workflow-reality-interface.md) | 안전관리 직무, 업무 흐름, 현실 입력, 조치·기록 연결 |

세션 기록의 내용이 현재 정본과 다르면 **01~04의 현재 문서를 우선**한다.
